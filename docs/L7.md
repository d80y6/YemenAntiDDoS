# Layer 7 (L7) Inspection

## Overview

YemenAntiDDoS inspects application-layer traffic on captured payloads to detect and surface
HTTP floods, Slowloris connections, and TLS ClientHello bursts. Parsing runs on the Node
using `shared/l7` and results are aggregated in-memory per destination, then pushed to the
Controller via the existing `CriticalEventStream` as `pb.CriticalEvent` messages.

## Node Configuration

Add an `l7` block to the Node configuration. L7 parsing requires the first ~512 bytes of each
TCP payload, so ensure `sample_bytes` is set to at least 512 on every XDP interface.

```yaml
l7:
  enabled: false
  window_seconds: 1          # aggregation window
  http_rps: 1000             # HTTP requests/s per destination
  tls_hsps: 500              # ClientHellos/s per destination
  slowloris_conns: 50        # slow-open connections per destination
  max_tracked_destinations: 4096
  max_flows: 8192
  max_open_fragments: 256
  sample_bytes: 512
```

## Data Flow

1. Packets captured by the XDP datapath are sampled/parsed.
2. `l7collector.Collector` tracks HTTP requests, Slowloris connection patterns, and TLS
   ClientHello handshakes per destination IP within sliding windows.
3. When thresholds are exceeded, events are emitted as `CriticalEvent` with `EventType`
   (`l7_http_flood`, `l7_slowloris`, `l7_tls_clienthello`) and details encoded in `Counters`
   (e.g. `http_path:/login`, `http_method:GET`, `tls_sni:example.com`, `src:<ip>`).
4. The Controller receives these events via gRPC `CriticalEventStream` and feeds them into
   `controller/internal/l7store` for real-time aggregation and querying.

## Console

The **L7** dashboard (`/l7`) displays:
- KPI cards for HTTP floods, Slowloris, and TLS ClientHello
- Stacked-bar chart of events over time
- Top destinations and sources
- Reporting nodes
- Recent events table with type, destination, details, and counts

## API Endpoints

| Endpoint | Description |
|----------|-------------|
| `GET /api/l7/summary?window_minutes=1..240` | Aggregated L7 statistics, time series, top targets/sources, and recent events |
| `GET /api/l7/events?limit=1..1000` | Recent L7 events in newest-first order |

## Notes

- L7 aggregation is in-memory on the Controller (no database persistence) for low-latency
  real-time dashboards.
- The Node aggregates over windows and emits events to the Controller; the Controller
  maintains its own bounded store (`l7store`) with ring buffers and time-based pruning.
